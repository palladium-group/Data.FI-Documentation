## Operating model

```mermaid
flowchart LR
  M[Monitor] --> S[Support] --> L[Learn] --> R[Release] --> I[Improve]
```

| Activity | Focus |
|---|---|
| Monitor | System, workflow, integration, data quality, and adoption |
| Support | Triage users and resolve incidents |
| Learn | Review evidence and user feedback |
| Release | Prioritize, test, approve, and communicate changes |
| Improve | Strengthen service delivery and operations |

Continuous controls cover access review, security management, backup and recovery, documentation, vendor management, and cost monitoring. Document them in an operational runbook: monitoring, routine tasks, incidents, recovery, escalation, and service ownership.

## Product and service measures

| Kind | Examples |
|---|---|
| Product | Active use, task completion, sync health, referral closure, data timeliness, integration success, and support performance |
| Service | Country-approved measures of coverage, quality, continuity, equity, commodity availability, surveillance, and outcomes |

Service measures come from the responsible program. The system should be able to produce them. It should not invent them.

## Sustainability and scale

A sustainable digital community system needs institutional ownership, a stable product team, operating capacity, recurrent financing, controlled configuration, maintainable integrations, documented releases, trained users, and measurable value.

Scale decisions should consider readiness and service quality, not deployment volume alone.
